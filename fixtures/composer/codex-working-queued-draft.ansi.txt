
  As video terminals became more common, editors could display a larger portion of a document at once. This led to screen editors, which let users move a cursor through visible text and make
  changes interactively. [0m[38;5;6mvi[0m, developed by Bill Joy for BSD Unix in the late 1970s, grew from an earlier editor called [0m[38;5;6mex[0m, which itself extended the line-oriented tradition of [0m[38;5;6med[0m. The division
  between command mode and insert mode was partly a response to the limitations of early terminals and communication links. Instead of assigning every key an editing action, [0m[38;5;6mvi[0m used compact
  commands that could be sent efficiently over slow connections. Its modal design also made complex text transformations possible without relying on menus or a mouse.

  Around the same period, Richard Stallman began developing Emacs, initially at the Massachusetts Institute of Technology. Emacs was based on the idea that an editor should be extensible through a
  programming language. Rather than treating editing as a fixed collection of commands, Emacs allowed users to redefine behavior, add features, and build specialized modes. Over time, Emacs became
  an environment for programming, email, documentation, version control, and interactive development. Its extensibility influenced later editors and helped establish the idea that an editor could
  become a personalized computing environment rather than merely a document window.

  The personal-computer revolution introduced a different set of priorities. Editors such as WordStar, released in the late 1970s, were designed for users who wanted to write documents on
  relatively inexpensive machines. They offered formatting commands, keyboard shortcuts, and support for printers. WordPerfect became another major word-processing system during the 1980s. These
  applications blurred the boundary between text editing and document production by adding fonts, pagination, margins, and layout controls. Although they were not primarily programming editors,
  they demonstrated that text manipulation could become a mainstream desktop activity.

  Graphical user interfaces transformed editing again. The Macintosh and Microsoft Windows popularized editors with menus, toolbars, scrollbars, dialog boxes, and mouse-based selection. Users no
  longer needed to memorize command sequences to perform basic operations. The clipboard, drag-and-drop interaction, proportional fonts, and visible formatting made editing more accessible to
  nontechnical users. At the same time, programmers continued to favor command-driven tools because they were fast, scriptable, and usable over remote connections.

  During the 1980s and 1990s, programming editors became increasingly specialized. Editors added syntax highlighting, automatic indentation, code navigation, compiler integration, and debugging
  support. These features helped produce the modern integrated development environment, or IDE. Systems such as Turbo Pascal’s development environment combined editing, compilation, and execution
  in one interface. Later IDEs for Java, C++, and other languages added project management, refactoring, graphical debugging, and source-control integration.

  The rise of the internet and open-source software expanded the editor ecosystem. Vim, a descendant of [0m[38;5;6mvi[0m, added extensive configuration and scripting while preserving modal editing. Emacs
  continued to evolve through packages and community extensions. Editors such as TextMate and Sublime Text emphasized speed, visual polish, plugins, and multiple cursors. Atom introduced a web-
  technology-based extension model, while Microsoft’s Visual Studio Code combined a lightweight editor with language servers, debugging, version control, integrated terminals, and a large
  extension marketplace.

  Remote work and cloud computing also renewed interest in terminal editors. Tools such as [0m[38;5;6mnano[0m offered a simpler command-line experience for users who found modal editors difficult to learn.
  Terminal multiplexers made it possible to keep editors running on remote machines after an SSH connection ended. Web-based editors extended the model further by allowing documents and
  development environments to run in browsers, often with shared access and synchronized state.
